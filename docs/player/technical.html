00灰模接入 v2

现已加入六个真实模型分件：双臂、头部、头发、上衣与裤鞋。采用 LOD2（第三档），合计 72,346 顶点、87,238 三角形。灰色材质用于观察动作，当前装配不是游戏完整服装还原；头发透明裁切、贴图、武器、布料与表情尚未接入。

主 Mesh 与配套 streaming 文件共同提供顶点数据。C# 导出位置、法线、三角形、骨骼父子关系、局部绑定矩阵、逆绑定矩阵和蒙皮权重；本样本最多用到 7 个权重，保留在 8 槽数据内，不裁成 4 个。

浏览器按名称将 MOT 轨道匹配到各模型分件。未被轨道驱动的辅助骨保留局部绑定变换，并跟随父骨。每帧计算世界变换与逆绑定矩阵的乘积，再按所有权重变形顶点。位置通过 CPU 蒙皮更新，Three.js 负责 WebGL 灯光、材质和显示。当前使用专用 model.js 数据，而不是 GLB；这样可直接检查原始矩阵和完整权重。

新增文件：model.js（网格及蒙皮数据）、model-view.js（蒙皮和渲染）、vendor/three.min.js（本地依赖）。新增灰模、灰模＋骨架、线框与绑定姿态开关。骨骼名称只在原骨架模式显示；Add 片段自动退回骨架，范围着色不修改模型运动。

验证：六个分件的绑定矩阵最大误差约 2.27×10⁻⁷；持枪、抬枪和换弹各检查五个时间点，动画与模型同名骨骼的位置最大差约 4.55×10⁻⁷。浏览器未报 JS 错误，截图已检查。局部衣物接缝、头发片面和辅助骨变形仍可见；这些检查不等于已还原游戏物理和材质。

01整体架构

这个网页是一个离线动画播放器：先用 C# 将游戏 MOT 与 Mesh 资源解码为浏览器数据，再由 JavaScript 根据播放时间计算骨骼姿态。骨架模式采用 Canvas 2D；身体灰模采用 CPU 蒙皮与 Three.js WebGL 渲染。

项目没有使用 React 或 Vue，也不依赖在线服务。v2 身体灰模采用随网页附带的 Three.js；下文 Canvas 2D 描述针对保留的骨架模式。骨架模式中的坐标和运动是三维的，最终投影到 Canvas 2D；灰模模式使用 Three.js 相机、灯光和材质，两条渲染路径共用 MOT 采样逻辑。

03游戏资源的解码与导出

导出器位于 scripts/PlayerExport/Program.cs，使用 ReeLib 的 MotlistFile、MotFile 等类型读取资源。程序根据已有的有效文件清单，选择里昂的手枪动作文件，并导出 14 条动画：四方向移动、抬枪、持枪、放下枪、左右转身、射击、两种换弹，以及两条换弹补偿轨道。

骨架数据

每根骨骼保存名称、父骨骼索引、参考姿态的局部位置和局部旋转。父骨骼索引用来表达肩膀、上臂、前臂和手掌之间的连接关系。

动画轨道

每条轨道对应一根骨骼，分别保存位置、旋转、缩放的时间与数值。导出器使用 bone hash 匹配轨道和骨架；存在无法匹配的轨道时会报错。关键帧帧号按轨道帧率换算为秒，旋转四元数在导出时归一化。

{
  bone: 骨骼索引,
  position: { times: [...], values: [...] },
  rotation: { times: [...], values: [...] },
  scale:    { times: [...], values: [...] }
}

当前每条动画包含 67 或 69 根骨骼、67 条动画轨道。动画时长依据资源帧数与帧率导出；它是资源时间基准，不代表游戏状态机中最终采用的播放持续时间。

04为什么双击 HTML 就能使用

本地 file:// 页面通过 fetch 读取 JSON 时，可能受到浏览器本地访问策略限制。因此播放器使用普通脚本加载 motions.js，由脚本直接建立全局变量：

window.MOTION_DATA = { /* 骨架与动画数据 */ };

player_index.html 先加载 motions.js、masks.js 和 math.js，再加载本地 Three.js、model.js、model-view.js，最后启动 app.js。应用启动时数据已经就绪，无需网络请求。motions.json 作为工具用副本保留，播放器不会重复加载它。本说明页同样只使用本地 HTML 和 CSS。

05播放时间如何变成姿态

math.js 的 sample 函数针对每根骨骼的位置、旋转、缩放轨道，寻找当前时间左右相邻的关键帧。定位使用二分查找，避免每次从头扫描整个轨道。

例如当前时间为 0.35 秒，两侧关键帧为 0.30 秒和 0.40 秒，则插值比例 u = (0.35 − 0.30) / (0.40 − 0.30) = 0.5。

位置和缩放：线性插值

当前值 = 前一个值 +（后一个值 − 前一个值）× u

旋转：四元数球面插值

旋转使用四元数表示，采用 SLERP 在两个姿态间过渡。代码会在需要时翻转其中一个四元数以选择较短旋转路径；当两个旋转非常接近时，使用归一化线性插值，避免数值不稳定。

缺少位置或旋转轨道时，回退到骨架参考姿态；缺少缩放轨道时使用 [1, 1, 1]。当前时间早于首个关键帧或晚于末个关键帧时，保持相应端点值，所以末关键帧之后会保持姿态直至该播放周期结束。

06骨骼如何沿层级联动

轨道描述的是骨骼相对父节点的局部变换。计算手掌的世界位置时，必须先计算前臂、上臂等祖先节点的姿态，再逐层组合。

世界位置 = 父世界位置
         + 父世界旋转 ×（父世界缩放 × 局部位置）
世界旋转 = 父世界旋转 × 局部旋转
世界缩放 = 父世界缩放 × 局部缩放

因此上臂转动时，前臂和手掌会随之移动，同时仍能叠加各自的局部运动。pose 函数递归计算父节点，并缓存本次计算中已完成的结果；它也会检查骨架父子关系中的循环，避免无限递归。

这是一套以位置、四元数和分量缩放组合姿态的实现，当前没有完整矩阵剪切变换的处理。

07Canvas 2D 如何呈现三维骨架

  1. 计算当前时刻所有骨骼的三维世界坐标。
  2. 应用跟随根节点选项和视角旋转。
  3. 将三维坐标透视投影为画布坐标。
  4. 按深度排序，连接父子骨骼，绘制关节点与名称。

视角使用 yaw（左右旋转）、pitch（上下俯仰）和 zoom（缩放）三个变量。简化透视因子为：

f = 4 / (4 + z)

旋转后的深度 z 会影响屏幕上的大小，产生近大远小的效果。骨骼按深度由远到近绘制，形成基本的遮挡关系；原 Canvas 骨架模式没有 WebGL 的逐像素深度测试，因此交叉线段的遮挡只是近似结果；灰模模式由 WebGL 渲染模型表面，叠加骨架则关闭深度测试以便观察。

地面网格也使用同一投影函数绘制，会随视角一起改变透视。Canvas 的实际像素尺寸按 devicePixelRatio 调整，让高分屏上的线条更清晰。左右侧与中轴分别使用暖橙、浅蓝和灰白色，手指和辅助骨使用更细的线条。

08播放控制与用户交互

播放器通过 requestAnimationFrame 刷新。每次计算距离上一帧经过的秒数 dt，再按所选倍速推进时间：

time += dt * speed;

渲染刷新频率与资源帧率分离；逐帧操作则严格按资源的 1 / fps 秒推进。

操作内部行为
播放 / 暂停切换 playing；从结束位置播放时先回到起点。
上一帧 / 下一帧暂停并减去或增加 1 / fps 秒，限制在有效时长内。
拖动时间轴暂停并将播放时间设为滑块值。
循环 / 非循环到结尾后对时长取余，或停在结束位置。
搜索 / 切换动作按中文名、原始名称或编号筛选；切换后时间归零并更新资源信息。
拖动 / 滚轮Pointer Events 调整 yaw、pitch；滚轮按指数关系调整 zoom，并限制范围。
空格在焦点不位于输入框、下拉框或按钮时切换播放状态。

单次时间推进最多采用 0.1 秒，避免卡顿或返回后台页面时大幅跳跃；因此后台停留期间不会完整追赶实际经过的时间。暂停时刷新循环仍在运行，显示选项的更改也能及时反映到画面。

骨骼显示选项

手指与辅助骨通过骨骼名称规则筛选，名称标签绘制在对应关节点旁。“跟随根节点”从全部关节位置中减去根骨骼的水平位移，保留垂直运动。这是显示坐标调整，尚未实现游戏角色的根运动提取与移动逻辑。

09Mask 与 Add 的实际含义

Mask：骨骼范围着色

masks.js 中的配置来自 reports/phase2/handgun_evidence.json。选择 Mask2、Mask4 或 Mask11 后，程序按骨骼名称匹配，将对应关节范围高亮，其余骨骼变暗。配置中不属于当前骨架的关节不会绘制。

当前 Mask 只帮助观察骨骼覆盖范围，没有执行动画遮罩混合或按权重融合两段动作。

Add：补偿轨道单独预览

配套 Add 片段目前作为独立轨道显示。真正叠加到基础动作，需要还原参考姿态、叠加规则和权重等信息；本版本未执行这些步骤。补偿片段出现收缩或偏离正常人形的姿态，不足以单独证明解码错误，因为它可能需要与基础动作共同解释。

10界面布局与本地部署

播放器使用原生 HTML 与 CSS。CSS Grid 组织动作栏和工作区，Flexbox 排列控件，绝对定位将标题、图例和视角按钮叠加在画布上。媒体查询针对窄屏调整为较小侧栏或上下布局。字体使用系统字体，无需下载外部资源。

网页不需要数据库或应用后端。直接打开 player_index.html 即可使用，也可以在 player 目录运行：

node server.cjs

随后访问 http://127.0.0.1:8765。server.cjs 只提供 docs/ 内的静态文件，并仅监听本机地址。两种访问方式下，姿态计算与绘制都发生在浏览器中。

11已有验证与当前边界

项目的 verify.cjs 检查 14 条动画的轨道时间顺序、数值有效性、姿态采样和运动变化，并对四元数插值与旋转进行基础检查。README 记录了共 854 次姿态采样通过，以及 browser-check.cjs 对加载、播放、暂停、逐帧、搜索、切换、时间轴、视角与非循环结束等交互的检查通过。

这些是项目已有验证记录，不代表完整还原了游戏运行时行为，也不等于覆盖全部资源格式和所有浏览器环境。

当前版本支持源轨道驱动的身体灰模与骨架。

已接入角色 Mesh 与蒙皮权重，尚未接入贴图、武器、布料、表情及游戏状态机、IK、动画事件、根运动策略和运行时混合。因此它适合研究模型绑定与源动画，不能直接等同于游戏最终画面。

后续完整角色预览可在现有 Three.js 灰模渲染上继续加入贴图材质、头发透明裁切、武器和表情，并还原基础动作、补偿动作与遮罩的组合逻辑。当前 CPU 蒙皮也可进一步优化为 GPU 蒙皮或标准 GLB 管线。
