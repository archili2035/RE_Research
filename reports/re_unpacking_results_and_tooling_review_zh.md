# 生化危机解包成果、数据缺口与后续研究选型

整理日期：2026-11-06。

本报告汇总本项目已完成的 Requiem 静态资源研究、当前限制，以及公开工具支持情况。工具支持信息来自本次查阅的项目文档；尚未对 RE4 重制版、RE8 等候选作品进行本地全量解包或运行时测试。

## 1. 结论与研究对象

当前解包对象是 **Resident Evil Requiem**，不是《生化危机8：Village／村庄》。公开工具资料不支持“8 代太新，因此普遍难以解包”这一判断：RE8 和 RE4 重制版均有模型、动画、结构化配置与运行时检查工具支持。

如果继续研究“里昂的动作与第三人称 3C”，建议优先使用 **《生化危机4 重制版》作为对照项目**，同时保留 Requiem 已有成果。这里的 3C 指角色（Character）、镜头（Camera）与操控（Control）。

目前的主要瓶颈已经不只是打开资源包，而是把资源、配置与游戏运行时的最终行为对应起来。改用工具更成熟的作品，可以降低格式适配与接口探索成本，但不能让输入延迟、取消窗口等实测数据自动出现在静态资源中。

## 2. 已完成的成果

以下数量针对已提取的 ch0100 有效版本样本，不是整个游戏或里昂全部资源的完整统计。统计未把旧补丁副本叠加计算，但仍可能遗漏未提取、未命中路径清单或其他角色编号下的资源。

| 研究部分 | 已完成内容 | 实际价值与边界 |
|---|---|---|
| 角色识别 | 将 ch0100 高可信度对应到里昂 | 关联角色配置与动作资源；不是依据编号本身猜测 |
| 动画资源索引 | 310 个 motlist、6 个 motpack、23,717 个槽位 | 梳理按武器、用途及变体组织的引用；槽位不是独立动画数量 |
| 动画载荷统计 | 6,185 份实际存储的 MOT 片段、122 份动作树数据 | 动画片段与组合规则分别计数；未进行全部内容去重 |
| 动画分类 | 移动、持枪、射击、换弹、受击等分类统计 | 用途分类包含名称规则推断，尚未逐条播放确认 |
| 骨骼与模型 | 六分件灰模、骨架和蒙皮统计；骨骼名称并集为 710 | 710 不是已验证的运行时总骨骼数；模型采用当前导出的 LOD2 和子网格 |
| 动画播放 | 网页接入 14 条演示动画 | 包含移动、举枪、射击、换弹等，只是演示集 |
| 状态与调用关系 | 解析 3 套状态机，整理 3,836 条关系，目标引用均能解析 | 包括层级、入口选择和状态转移，不能全部理解为时间顺序 |
| 镜头配置 | 解析选定的 279 份相机配置，无解析失败 | 解析成功不代表字段语义和最终镜头均已验证 |
| 运行时工具 | 完成采集器原型、安装脚本、CSV 转换器和模拟测试 | 尚未实机验证；本项目运行时测量数量仍为 0 |

最重要的成果，是将“有哪些资源”与“配置如何引用这些资源”关联起来。例如射击不仅调用角色动画，还涉及武器动画、开火逻辑与再次射击的等待条件，因此源动画时长不能直接当成射速。

## 3. 缺陷及尚不能获得的数据类型

“尚不能获得”不等于永久无法获得。需要区分三种情况：我们还没有解析的数据、必须运行游戏才能测量的数据，以及发行资源通常无法完整还原的制作资料。

| 数据类型 | 当前缺口 | 后续获取途径或限制 |
|---|---|---|
| 全量资源与完整引用 | 样本覆盖不完整，仍有 106 个未解析槽位 | 补路径清单、特殊引用解析和其他资源依赖 |
| 全部动画的正确播放 | 统计了 6,185 份片段，但网页只接入 14 条；未逐条验证 | 批量解码、异常检查、抽样与游戏画面对照 |
| 动画内容真正去重 | 按文件与存储位置计数，不同文件可能保存相同动作 | 比较解码后的轨道内容，而不是只比较名称 |
| 最终动画混合 | 未测得实际时刻的层权重、过渡时间与附加动画贡献 | 运行时采集动画层，并验证字段含义 |
| 最终角色姿态 | 网页未完整复现 IK、脚底防滑、瞄准约束、布料与辅助骨控制 | 读取运行时骨骼姿态，或逐项还原求解过程 |
| 输入响应与取消窗口 | 按键何时被接受、能否缓存、何时允许打断均未实测 | 输入记录、状态记录与录像对齐 |
| 弹药与开火事件 | 实际扣弹、补弹、生成子弹或命中判定时刻未获取 | 定位武器对象和事件接口；不能只用动画姿态代替 |
| 移动手感 | 实际加减速、转向响应、根运动与移动控制的贡献未确定 | 记录位置、朝向、输入与动作随时间的变化 |
| 最终镜头 | 配置值不等于实际 FOV、镜头位置、碰撞修正和后坐力结果 | 采集最终相机变换与投影参数 |
| 原始制作工程 | Maya 控制器、制作约束、原始动捕、设计注释与源码未获得 | 普通解包不能承诺恢复；发行资源可能已烘焙、压缩或剔除这些信息 |

### 3.1 静态配置不等于完整行为逻辑

状态机关系解析成功，不等于游戏行为已经完整还原。资源可以保存“调用某个条件判断”的名称与参数，而判断算法本身可能位于可执行代码中。读取到条件名称，不能据此宣称已经知道其全部优先级、计时单位或执行时机。

例如，动画中手接触弹匣的时刻，不必等于游戏增加弹药数的时刻；源射击动画的结束帧，也不必等于允许再次开火的时刻。

### 3.2 灰模播放器不等于游戏动画系统

现有网页用于观察选定的资源片段，尚未完整复现材质、部分模型层、面部、物理和程序化修正。没有匹配动画轨道的辅助骨保持局部绑定姿态并跟随父骨，不能把其表现当成游戏中的最终效果。

六分件的 710 个骨骼名也只是名称并集。同名不保证绑定参数相同，分件数量不能直接相加作为角色独立骨骼数量。

### 3.3 采集器仍处于原型阶段

采集器已有开始、停止、保存、接口探测、缺失数据保留与保存失败重试机制，并通过本地模拟测试。尚未在游戏中确认对象访问路径与动画字段。

当前没有已验证的弹药数、游戏实际接受的输入、相机参数或精确毫秒计时。回调样本序号不是录像帧号，整秒系统时间也不能用于输入延迟分析。模拟测试通过不能替代 RE 引擎中的实机验证。

## 4. 较新作品的工具支持调研

本次按资源提取、模型材质、动画播放导出、结构化配置和运行时检查分别评估。下表是依据公开支持范围及本项目目标作出的选型判断，不是各作品全量资产解包成功率排名。

| 候选作品 | 已有工具证据 | 对本项目的建议 |
|---|---|---|
| 生化危机4 重制版 | RE Mesh Editor、Noesis RE 插件、RE_RSZ 和 EMV-Engine 均列出支持 | 首选对照：贴近里昂第三人称持枪、移动与换弹研究 |
| 生化危机8：村庄 | 同样有上述主要工具支持 | 适合第一人称动作与镜头研究，不能简单认定为难解包 |
| 生化危机2／3 重制版 | 多套工具支持，部分明确区分 RT 与非 RT 版本 | 可作为更早的对照样本，需匹配游戏与工具版本 |
| Requiem | 已有模型与配置工具支持，本项目也已解析大量资源 | 保留现有成果；当前动画和采集链仍需实机校准 |

### 4.1 模型、材质与资源浏览

[RE Mesh Editor](https://github.com/NSACloud/RE-Mesh-Editor) 支持 RE2／3 重制版、RE4 重制版、RE8 和 RE9，主要处理模型、材质及贴图。模型支持不能直接推导为完整动画系统支持。

[RE Asset Library](https://github.com/NSACloud/RE-Asset-Library) 提供 RE 引擎资源浏览与提取能力，可以作为资产定位工具。上述两个原仓库均已归档，作者声明停止维护；选用时应记录并固定实际可用的工具版本，而不是假设会持续适配后续游戏更新。

### 4.2 动画导入、播放与导出

[Noesis RE 插件](https://github.com/alphazolam/fmt_RE_MESH-Noesis-Plugin) 明确列出 RE4 重制版和 RE8，文档介绍了加载 motlist、模型与动画联合预览，以及多动画 FBX 导出。它比单纯支持模型导出的工具更直接符合本项目的动画研究需求。

支持列表不保证所有片段、资源变体和补丁版本都能正确转换，仍应先用小样本核验。

### 4.3 配置、状态机与结构化数据

[RE_RSZ](https://github.com/alphazolam/RE_RSZ) 支持 RE4 重制版和 Village，可处理 USER、FSMV2、MOTFSM、BHVT 等带 RSZ 数据的资源。作者也建议参考 REECE、REE-Lib-Resources 或 REasy 获取较新的类型数据与编辑能力。

结构化资源解析解决的是字段与引用问题，不代表已经获得可执行代码中的方法实现。

### 4.4 游戏内观察与运行时检查

[EMV-Engine](https://github.com/alphazolam/EMV-Engine) 列出 RE4 重制版和 RE8，提供动画定位、速度控制及动作状态检查等功能。部分功能具有特定游戏限制，不能把总支持列表理解为每项功能都对所有游戏有效。

[REFramework](https://github.com/praydog/REFramework) 提供运行时脚本与对象检查基础，也是本项目采集器采用的框架。框架支持某款游戏，不等于我们的角色、武器或镜头字段已经验证。

## 5. 建议的后续路线

保留 Requiem 项目，新增一个 RE4 重制版的小规模验证样本。先只选择里昂、一把手枪，以及站立、移动、举枪、单发和换弹这组动作。

依次验证：

1. 模型、骨架和动画是否能用现成工具正确导出、关联并播放。
2. 游戏内是否能观察到对应的动作库编号、动作编号、动画时间与状态变化。
3. 是否能将一段录像、源动画片段和运行时状态记录对应起来。

通过以上小样本，才能判断相较 Requiem 实际节省了多少格式适配和接口探索工作，再决定是否扩大提取范围。

即使使用 RE4 重制版，输入延迟、取消窗口、最终混合权重和镜头响应仍需要运行时测量。选择较成熟的工具生态，主要是降低获取与验证这些证据的成本，不是消除静态资源研究本身的边界。
